Aster is a peer-to-peer application SDK for services that run across developer
machines, customer networks, and cloud instances. It combines typed RPC,
content-addressed storage, replicated documents, and coordination through a
shared Rust engine, with APIs for Rust, Python, TypeScript, Go, Java, and .NET.

## Why use it?

A service on a changing network needs a stable identity and a way for callers
to reach it. A distributed application also needs to decide who may act,
which data can converge later, and which mutations must have one agreed order.
Aster provides separate tools for those decisions:

- [Peer connectivity](/docs/concepts/transport/) uses endpoint public keys,
  direct-path attempts, and relay fallback.
- [Typed services](/docs/concepts/contract-identity/) identify their contracts
  across languages; [method permissions](/docs/concepts/trust-model/) restrict calls.
- [Blobs and documents](/docs/guides/data/) transfer content and replicate references.
- [Coordination and leases](/docs/guides/coordination/) serialize critical state,
  with fences that the protected resource must enforce.

Aster is a public preview. Packages, language APIs, and feature
coverage have different boundaries. Read [release compatibility](/docs/reference/compatibility/)
when choosing a language or moving from current source to a released package.

## How it fits together

<SdkLayers />

The shared engine handles transport and RPC dispatch. Application handlers run
in the language you choose. [Iroh](https://iroh.computer/) provides peer
connectivity and data protocols; [Apache Fory](https://fory.apache.org/)
provides the cross-language payload format. Read the
[architecture](/docs/reference/architecture/) and [trust model](/docs/concepts/trust-model/)
for the boundaries between connectivity, data, and authorization.
