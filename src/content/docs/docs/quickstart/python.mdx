## Define a service

A **service** is a class that exposes one or more methods callable by remote consumers. You write it like a regular class; Aster handles the wire format, transport, and remote dispatch.

<Tabs syncKey="language">
<TabItem label="Python">

Create `hello_service.py`:

```python
from dataclasses import dataclass
from aster import service, rpc, wire_type


@wire_type("hello/HelloRequest")
@dataclass
class HelloRequest:
    name: str = ""


@wire_type("hello/HelloResponse")
@dataclass
class HelloResponse:
    message: str = ""


@service
class HelloService:
    @rpc
    async def say_hello(self, req: HelloRequest) -> HelloResponse:
        return HelloResponse(message=f"Hello, {req.name}!")
```

`@dataclass` defines the data fields, `@wire_type` gives each type an explicit wire tag, `@service` identifies the service, and `@rpc` exposes the method. See [Defining services and types](/docs/guides/services) for the contract rules.

</TabItem>
<TabItem label="TypeScript">

Create `service.ts`:

```typescript
import { Service, Rpc, WireType } from '@aster-rpc/aster';

@WireType("hello/HelloRequest")
export class HelloRequest {
  name = "";
  constructor(init?: Partial<HelloRequest>) { if (init) Object.assign(this, init); }
}

@WireType("hello/HelloResponse")
export class HelloResponse {
  message = "";
  constructor(init?: Partial<HelloResponse>) { if (init) Object.assign(this, init); }
}

@Service({ name: "HelloService", version: 1 })
export class HelloService {
  @Rpc()
  async sayHello(req: HelloRequest): Promise<HelloResponse> {
    return new HelloResponse({
      message: `Hello, ${req.name}!`,
    });
  }
}
```

`@Service` identifies the service, `@Rpc` exposes its method, and `@WireType` gives each exported data type an explicit wire tag. See [Defining services and types](/docs/guides/services) for the contract rules.

Before running, generate type metadata with `npx aster-gen` — this reads your TypeScript source and emits `aster-rpc.generated.ts`, which `AsterServer` auto-imports on startup. See [TypeScript Build Setup](/docs/guides/typescript-build-setup) for details and bundler plugin options.

</TabItem>
</Tabs>

## Run a producer

A producer is the node that hosts the service.

<Tabs syncKey="language">
<TabItem label="Python">

Create `producer.py`:

```python
import asyncio
from hello_service import HelloService
from aster import AsterServer


async def main():
    async with AsterServer(services=[HelloService()]) as srv:
        print("Producer ready at:", srv.address)
        await srv.serve()


asyncio.run(main())
```

```bash
python producer.py
```

</TabItem>
<TabItem label="TypeScript">

Generate type metadata, then create `producer.ts`:

```bash
npx aster-gen
```

```typescript
import { AsterServer } from '@aster-rpc/aster';
import { HelloService } from './service.js';

const server = new AsterServer({
  services: [new HelloService()],
});
await server.start();
console.log("Producer ready at:", server.address);
await server.serve();
```

```bash
npx tsc
node producer.js
```

</TabItem>
</Tabs>

In dev mode (no `ASTER_*` environment variables set), the server:

- Generates an ephemeral root key and node identity (no files needed).
- Opens the consumer gate so consumers can connect without credentials.
- Serves RPC, blobs, docs, and gossip on a single endpoint.
- Prints an `aster1...` address for consumers to connect to.

## Run a consumer

A **consumer** is the node that calls into a producer's services. Consumers don't need access to the service's source code -- they discover methods from the producer's published contract at runtime, then call them by name.

The producer and consumer can run on separate networks. Aster attempts a direct connection and uses a relay when needed. Connectivity still requires a reachable direct or relay path. The `aster1...` address contains the endpoint identity and connection hints.

<Tabs syncKey="language">
<TabItem label="Python">

Create `consumer.py`:

```python
import asyncio
from aster import AsterClient


async def main():
    async with AsterClient() as c:
        # The dynamic proxy builds XLANG requests from the published contract --
        # methods are discovered from the producer's published contract.
        hello = await c.proxy("HelloService")
        resp = await hello.say_hello({"name": "World"})
        print(resp["message"])  # Hello, World!


asyncio.run(main())
```

Run it, passing the producer's address:

```bash
# macOS / Linux
ASTER_ENDPOINT_ADDR="<paste from producer output>" python consumer.py
```

```powershell
# Windows (PowerShell)
$env:ASTER_ENDPOINT_ADDR="<paste from producer output>"; python consumer.py
```

`AsterClient` reads `ASTER_ENDPOINT_ADDR` from the environment and connects to the producer. `await c.proxy("HelloService")` returns a dynamic stub -- call methods on it like regular async functions. If you'd rather have typed classes (for IDE autocomplete and static checking), share the service definition module between producer and consumer and use `await c.client(HelloService)` instead -- see [Defining Services and Types](/docs/guides/services).

</TabItem>
<TabItem label="TypeScript">

Create `consumer.ts`:

```typescript
import { AsterClientWrapper } from '@aster-rpc/aster';

const client = new AsterClientWrapper({
  address: process.env.ASTER_ENDPOINT_ADDR!,
});
await client.connect();

// The dynamic proxy builds XLANG requests from the published contract --
// methods are discovered from the producer's published contract.
const hello = await client.proxy("HelloService");
const resp = await hello.sayHello({ name: "World" });
console.log(resp.message); // Hello, World!

await client.close();
```

Run it, passing the producer's address:

```bash
# macOS / Linux
npx tsc
ASTER_ENDPOINT_ADDR="<paste from producer output>" node consumer.js
```

```powershell
# Windows (PowerShell)
npx tsc
$env:ASTER_ENDPOINT_ADDR="<paste from producer output>"; node consumer.js
```

</TabItem>
</Tabs>

## Connection behavior

The producer publishes its contract and prints an `aster1...` address. The consumer uses that address to connect, discover the contract, and invoke the greeting method. Transport authentication verifies the endpoint key; open development mode admits consumers without enrollment credentials.

Development mode uses an ephemeral identity, so the address changes after a restart. To try separate machines, copy the current address into the consumer’s `ASTER_ENDPOINT_ADDR`. Each machine needs a reachable direct or relay path.
