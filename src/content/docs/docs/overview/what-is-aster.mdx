Aster is a peer-to-peer application SDK with typed RPC services. Applications connect to an endpoint's cryptographic identity and use enrollment credentials and method permissions to control access. It is intended for services that run across developer machines, customer networks, and cloud instances.

Aster 0.3.893 is a public preview. It provides Rust, Python, TypeScript, Go, Java, and .NET APIs against the same Rust engine. The preview does not provide a general-availability stability guarantee.

## Endpoint identity and connectivity

Each endpoint has an Ed25519 keypair. Its public key, the `EndpointId`, identifies the peer independently of its IP address. The [Iroh](https://iroh.computer/) transport uses address hints and configured discovery mechanisms to find a path, authenticates both endpoints, and encrypts the connection.

Iroh attempts direct connectivity and can use a relay when a direct path is unavailable. Reachability still depends on network policy, available address information, and relay access. See [transport](/docs/concepts/transport/).

## Typed services and serialization

Define services in application code using the language's decorators, annotations, attributes, or Rust APIs. Aster derives a canonical contract and hashes it with [BLAKE3](https://github.com/BLAKE3-team/BLAKE3) to produce a `contract_id`. Implementations must agree on method names, wire types, and contract settings to compute the same identity.

[Apache Fory](https://fory.apache.org/) provides the default cross-language serialization format. Dynamic tools convert JSON input to typed XLANG payloads using a contract schema. Transport encryption applies to RPC traffic. See [serialization](/docs/concepts/serialization/) and [contract identity](/docs/concepts/contract-identity/).

## Access control and discovery

Enrollment credentials establish deployment membership. Method capability requirements restrict calls after admission. These protections depend on the configured trust policy; the quickstart's development settings allow unauthenticated application access. Read the [trust model](/docs/concepts/trust-model/) before deploying with sensitive data.

The [service registry](/docs/concepts/discovery/) uses Iroh documents, blobs, and gossip to replicate contract and endpoint information between participating peers. Applications can also connect using an explicit endpoint address.

## Language support

| Language | Preview surface |
| --- | --- |
| Rust | Supported facade and native transport access |
| Python | RPC API and native binding |
| TypeScript | RPC API and native binding |
| Go | RPC API through the C ABI |
| Java | RPC API through the native binding |
| .NET | RPC API through the C ABI |

Kotlin is not independently qualified in this preview. Cross-language interoperability requires compatible contracts and serialization settings; matching language support alone does not establish compatibility for every application type.
