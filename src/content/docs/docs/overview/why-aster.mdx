Aster addresses two application requirements: connecting services across networks where addresses can change, and deciding which calls an authenticated peer may make. For example, a remote agent can submit status updates while an operator has permission to issue commands.

## Requirements and operating conditions

| Your requirement | Aster mechanism | What to evaluate |
| --- | --- | --- |
| Reach workers whose addresses change | Persistent endpoint identity, direct paths, relay fallback | Preserve keys and test reachability through your firewalls and relays |
| Give operators and workers different permissions | Admission policy and method requirements | Issue credentials, verify attributes, and test denied calls |
| Keep state across a conversation | Session-scoped service instances | Bound memory and define recovery after disconnection |
| Exchange immutable job inputs | Content-addressed blobs | Retain content and ensure a provider remains reachable |
| Protect a single-writer operation | Coordination and fenced leases | Run the authority and enforce the fence at the resource |

These mechanisms reduce application plumbing, but each introduces an operating
responsibility. Compare a representative end-to-end workflow with your existing
network and RPC stack before adopting the preview.

## Connect using a persistent identity

An endpoint's Ed25519 public key identifies it across IP address changes, provided the application preserves its secret key. [Iroh](https://iroh.computer/) handles QUIC connectivity, direct-path attempts, and relay fallback. Applications can pass an endpoint address containing the identity and network hints instead of maintaining a stable service hostname.

This is useful when services run on developer laptops, customer networks, or edge machines. Network policy still matters: a firewall can prevent direct connections, and a relay must be reachable when a deployment needs one. See [transport](/docs/concepts/transport/).

## Separate identity from permission

The transport proves which endpoint holds a key. Aster's enrollment and capability checks determine what that endpoint may do within a deployment. Operators configure the trust root and issue credentials; service authors declare method requirements.

Development defaults are permissive. Configure and review the [trust model](/docs/concepts/trust-model/) before admitting peers to a deployment with sensitive operations.

## Define services in application code

Service definitions use language-native APIs. The following API fragment shows Python decorators; `TaskAssignment` and
`TaskAck` are application wire types, and the body is intentionally omitted:

```python
@service(name="TaskManager", version=1)
class TaskManagerService:
    @rpc
    async def assign_task(self, req: TaskAssignment) -> TaskAck:
        ...
```

The framework derives a canonical contract from the methods and wire types. Its `contract_id` lets clients and servers identify the interface they implement. Both sides must use matching names, types, and contract settings; a hash does not establish that their application behavior is correct.

Read [contract identity](/docs/concepts/contract-identity/) and [define a service](/docs/guides/define-a-service/).

## Keep state for a sequence of calls

Session-scoped services associate a service instance with a connection-scoped session ID. Method calls can share instance state until the session closes. This supports workflows such as an agent's task session without requiring an application to route every call by a separate session identifier.

Session state does not survive connection loss automatically. Applications that need recovery must persist or reconstruct it. See [session-scoped services](/docs/concepts/session-scoped-services/).

## Evaluate the preview

Aster is a public preview with Rust, Python, TypeScript, Go, Java, and .NET surfaces. Evaluate its package delivery, network behavior, and API stability against your deployment requirements. [Aster vs gRPC](/docs/overview/aster-vs-grpc/) describes the deployment choices; [your first service](/docs/quickstart/python/) shows the Python and TypeScript workflow.
