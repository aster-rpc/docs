## Cross-page fixes to coordinate

1. Use **connection + session ID + service** consistently. Remove “one instance per connection” shortcuts from service guides and MissionControl. Check shell explanation against the actual session protocol.
2. Scope credential admission by binding and transport. Python’s consumer handshake is not the universal native Rust/Go/.NET connection path. Remove retired producer-admission protocol claims after release verification.
3. Define one authoritative service/type guide and a stable vocabulary: endpoint identity, public ticket/address hints, enrollment credential, contract descriptor, payload schema, connection, call stream, and session.
4. Keep independent release tracks visible: SDK, CLI, generated API catalog, native ABI, source examples, and hosted registry. Link one versioned evidence record instead of repeating inconsistent status prose.
5. Turn conceptually sound new feature pages into complete task recipes. HTTP, exposure, grants, coordination, leases, topology, and baseline services need concrete inputs, ownership, output, failure handling, and next task.
6. Document configuration layers at both levels: construction of AsterConfig and the high-level wrapper’s identity/inline overrides. Avoid “environment always wins” when another layer overrides it.
7. Treat downloadable projects as first-class maintained sources: link the exact project used, show its file layout, qualify host/toolchain, and keep visible snippets synchronized.
